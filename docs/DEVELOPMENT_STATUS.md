# Development Status

## Public status

This documentation establishes the public scope of the Street Fighter II CPS1 to SNES project. No implementation milestones or hardware validation results are established by this documentation update. It makes no claim that a playable build is publicly available.

The target is standard Super Nintendo hardware without enhancement chips. The project is independent and non-commercial.

## Development areas

The following areas define what the project aims to evaluate. They are not a checklist of completed work.

| Area | Intended focus | Evidence for future status updates |
| --- | --- | --- |
| Gameplay and controls | Combat behavior, timing, movement, and input response | Described test scenarios and observed results |
| Visual presentation | Animation, stages, interface, and visual consistency | Reviewed observations with stated limitations |
| Audio | Music, sound effects, and synchronization | Listening and timing observations in defined scenarios |
| Game flow | Menus, match progression, and transitions | Results for identified player flows |
| Hardware validation | Stability and behavior on standard SNES hardware | Hardware tested, test scope, results, and known issues |

## Reporting progress

Public updates should describe concrete observations and distinguish intended work, work in progress, and verified results. A claim of verification should identify what was tested, the relevant revision or milestone, the test environment, and any limitations. Emulator observations alone do not establish verification on standard SNES hardware.

Do not infer overall completion from individual demonstrations or assign unsupported completion percentages. List unverified areas as unverified, and record known compromises without implying that every development area has been tested.

## Availability and scheduling

A progress report, demonstration, or internal milestone is not a public release. This document announces no download, release date, or delivery commitment. Future release availability must be confirmed by an explicit announcement under the [Release Policy](RELEASE_POLICY.md).

Public status updates must remain at the level of goals, observed behavior, and limitations. They must not disclose source code, internal tools, memory management details, conversion techniques, ROM files, patches, or copyrighted assets.
